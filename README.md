# dsh-clinic-intake

> 让患者在候诊时把主诉说清楚，医生接诊时少问 5 分钟。

诊前信息结构化插件：患者在候诊时回答六个固定问题（或自由描述），插件把回答整理成一份 **不超过 300 字** 的就诊摘要，医生接诊前扫一眼就知道主诉、病程、用药、过敏、既往史。

**只做信息整理，不做任何医学判断。** 不提供诊断、不提供分诊结论、不推荐用药，也不是医疗器械。

---

## 它解决什么问题

一个上午 30 个病人，医生或护士要重复问「哪里不舒服、多久了、吃什么药、有没有过敏、以前得过什么病」，再把回答手打进系统。重复问诊耗时间，而且录进去的多是一段没有结构的自由文本，后续查询和统计几乎不可能。

这个插件把这段重复劳动挪到候诊时间：患者在平板或前台电脑上填完，医生接诊时看到的是结构化字段 + 一段可直接粘贴进电子病历的摘要。

## 边界（硬约束）

| 做 | 不做 |
| --- | --- |
| 主诉结构化（部位 / 性质 / 病程） | 诊断、鉴别诊断 |
| 症状时间线整理 | 分诊等级、病情严重程度判断 |
| 用药史、过敏史、既往史提取 | 用药推荐、剂量建议 |
| 就诊原因分类标签（疼痛 / 呼吸 / 消化 …） | 检查或检验建议 |
| 300 字摘要生成与一键复制 | 对接 HIS / EMR 写库 |

插件不采集姓名、身份证号、电话、邮箱；如果患者误填，规则会在整理时把这类内容替换成 `[已隐去]`，原文不进入摘要，也不写入任何存储。默认全程内存处理，不发起任何外部网络请求。

## 两种用法

### 1. DSH Web 界面：会话头部的「候诊采集」按钮

安装后，会话头部会多一个 **🩺 候诊采集** 按钮。点开是一个六问向导：

1. 今天主要哪里不舒服？（主诉）
2. 这种情况多久了？（病程）
3. 有没有在吃什么药？（用药史）
4. 有没有药物或食物过敏？（过敏史）
5. 以前有没有得过什么病？（既往史）
6. 还有什么想告诉医生的？（补充，可留空）

填完点「生成摘要」，看到结构化摘要与字数（如 `218/300`），点「复制摘要」即可粘贴到电子病历系统。

> 向导在浏览器本地完成提取（与 Host 工具共用同一份规则核心），患者回答不会离开页面，也不经过任何服务端接口。

### 2. 候诊区平板：离线填写页

```
dsh 里说：用 clinic_intake_page 生成一份候诊填写页
```

会生成一个**单文件 HTML**（默认 `clinic-intake-form.html`），双击即可在任意浏览器打开，`file://` 也行，不需要服务器：

- 不联网、不写 localStorage 或 cookie，刷新即清空；
- 患者填完点「复制」，拿到一段「主诉：… / 病程：… / 用药：…」的文本；
- 医生把这段文本交给 `clinic_intake_extract`，或直接粘贴进 DSH 会话，由工具整理成摘要。

### 3. 命令行 / Agent 直接整理

```
clinic_intake_extract(
  chief: "右边太阳穴一跳一跳地疼，从前天开始",
  duration: "3 天",
  medications: "布洛芬，每天三次，每次一片",
  allergies: "青霉素过敏",
  history: "高血压 5 年",
  extra: "最近晚上睡不着"
)
```

也接受一整段标签文本（`text` 参数），逐字段参数优先：

```
主诉：右边太阳穴一跳一跳地疼
病程：3 天
用药：布洛芬，每天三次，每次一片
过敏：青霉素过敏
既往：高血压 5 年
补充：最近晚上睡不着
```

输出：

```json
{
  "chief_complaint": { "location": "太阳穴", "character": "跳痛", "duration": "3天", "raw": "右边太阳穴一跳一跳地疼，从前天开始" },
  "medications": [{ "name": "布洛芬", "frequency": "每天三次，每次一片" }],
  "allergies": ["青霉素过敏"],
  "past_history": ["高血压 5 年"],
  "free_text": "最近晚上睡不着",
  "reason_category": "疼痛",
  "missing_fields": [],
  "phi_redactions": [],
  "summary": "【就诊摘要】…",
  "summary_chars": 96,
  "labeled_text": "主诉：…"
}
```

摘要长这样：

```
【就诊摘要】
主诉：太阳穴·跳痛，持续3天
分类：疼痛
用药：布洛芬（每天三次，每次一片）
过敏：青霉素过敏
既往：高血压 5 年
补充：最近晚上睡不着
注：以上为患者自述整理，不含诊断与用药建议。
```

## 摘要的 300 字规则

- 硬上限 300 个 Unicode 字符（不是字节，也不是 UTF-16 码元）；
- 超长时按顺序压缩：先截短「补充」→ 再去掉「补充」行 → 逐条减少「既往」→ 截短原始主诉 → 最后硬截断并补 `…`；
- 返回值里的 `summary_chars` 是实际字数，`trimmed` 标记是否发生过压缩（Web 界面会提示）；
- 固定保留结尾的「不含诊断与用药建议」声明。

## 结构化提取是怎么做的

规则 + 关键词表，不依赖模型：

- **部位**：19 组部位词（太阳穴 / 头 / 咽喉 / 上腹 / 下腹 / 腰 / 皮肤 / 睡眠 …），具体部位优先于泛化部位；
- **性质**：15 组感觉词（绞痛 / 刺痛 / 跳痛 / 胀痛 / 干咳 / 咳痰 / 瘙痒 …）；
- **病程**：数字 + 单位（小时 / 天 / 周 / 月 / 年），兼容「半年 / 多年 / 反复发作 / 从上周开始」；
- **用药**：先把「布洛芬，每天三次，每次一片」这类条目合并成一味药，再拆出 `name` + `frequency`；
- **过敏 / 既往**：按顿号、逗号、分号、斜杠切分；「没有 / 无 / 否认」这类回答归为空列表，但「没有药物过敏，但吃海鲜会起疹子」不会丢掉后半句；
- **分类标签**：以主诉为准，主诉无法归类时才看其他字段。

改词表或改问题：编辑 `src/core/extract.js` / `src/core/questions.js`，然后 `npm run build`。

## 隐私与合规

- 不采集、不记录患者身份信息；误填的手机号 / 身份证号 / 邮箱 / 「姓名：xxx」在整理时被替换为 `[已隐去]`，只在 `phi_redactions` 里记录「隐去了哪一类」，不留原文；
- 默认纯内存：没有数据库、没有缓存文件、没有 localStorage；生成的 HTML 页面也不保存内容；
- 不联网：核心模块不导入 `node:` 内置模块、不调用 `fetch`，测试会静态检查这一点；
- 输出只用于医生阅读和复制，不写回 HIS/EMR；
- **本插件不是医疗器械，不提供诊断或治疗建议，仅辅助信息整理。** 最终判断与处置由接诊医生负责。

## 安装

```bash
dsh plugin add @liuhange/dsh-clinic-intake
```

Web 界面需要 `@deepseek-ai/dsh-web-app`（`dsh web` 默认带）。只装 CLI 则 Host 工具与离线填写页照常可用。

## 开发

```bash
npm install
npm test        # 构建 + 三个测试文件
npm run build   # lib/index.js（Host）与 lib/client.js（浏览器 bundle）
```

目录：

```
src/core/extract.js   规则提取（纯函数，零依赖）
src/core/summary.js   300 字摘要与压缩
src/core/page.js      离线填写页（单文件 HTML）
src/core/questions.js 六个问题
src/host/index.js     两个工具：clinic_intake_extract / clinic_intake_page
src/client/index.jsx  会话头部按钮与六问向导
test/                 五种主诉、摘要长度、PHI 与无持久化
```

测试覆盖：头痛 / 腹痛 / 咳嗽 / 皮疹 / 失眠 五种主诉的部位、性质、病程、分类标签；摘要 ≤300 字（含超长补充、超长用药与既往）；手机号 / 身份证 / 邮箱 / 姓名标签的隐去；核心模块无文件与网络依赖。

## FAQ

**能不能改成科室自己的问题？** 可以，改 `src/core/questions.js` 后重新 `npm run build`；字段名保持 `chief / duration / medications / allergies / history / extra` 即可。

**会不会自己连网？** 不会。插件不调用任何外部 API，Web 界面的提取也在页面内完成。

**能不能直接写进我们的门诊系统？** 不直接对接。摘要是给人读和复制的文本，粘贴目标由医生决定。
